## B. Objective
Make incidents real records with a guarded lifecycle and an append-only audit trail. Every later step (agent, repair, report, review, UI) reads and advances an incident through this module, and the state guards are how the system refuses to claim things it hasn't proven (no "diagnosed" without evidence, no "verified" without a red/green pair).

## D. Technical background
- **Feature folder pattern:** `router.py` (thin) → `service.py` (transitions, rules) → `repository.py` (SQLAlchemy only) with `schemas.py` for request/response and `models.py` for ORM.
- **State machine:** a dict of allowed transitions plus guard functions; one `transition()` entry point used everywhere. Illegal → domain exception → HTTP 409.
- **Append-only audit:** the repository exposes `add_event()` only; no update/delete method exists, so nothing can rewrite history.
- Only Track B writes migrations (assumption AS2).

## E. Implementation instructions
1. **Models** (`incidents/models.py`):
   - `Incident`: `id` (UUID), `case_id` (nullable), `service`, `symptom`, `source` (`lab_case`/`manual`/`github`), `state` (enum), `cause_class` (nullable), `base_sha` (nullable), `created_at`, `updated_at`.
   - `EvidenceItemRow`: `id` (`EV-…`), `incident_id` FK, `kind`, `service`, `content`, `sha256`, `path`, `line`, `ts`.
   - `AuditEvent`: `id`, `incident_id` FK, `actor` (`system`/`agent`/`reviewer:<name>`), `event_type`, `from_state`, `to_state`, `payload` (JSON), `payload_sha256`, `created_at`.
2. **States** (`incidents/states.py`): enum and `ALLOWED = {CREATED: {SNAPSHOT_LOCKED}, ...}` per [ARCHITECTURE.md](../ARCHITECTURE.md#data-flow-for-one-incident), including `DIAGNOSED → REVIEW_PENDING` (runtime_dependency) and `INCONCLUSIVE → REVIEW_PENDING`.
3. **Guards** (`incidents/service.py`): `DIAGNOSED` requires ≥1 evidence ID in the payload; `VERIFIED` requires `repro_before == "failed"` and `repro_after == "passed"` in the payload; `REVIEWED` requires a review ID. `transition(db, incident_id, to_state, actor, payload)` checks allowed + guard, updates state, writes the audit event in the same DB transaction.
4. **Schemas:** `IncidentCreate` (either `case_id` or `symptom`+`service`; validator enforces one of them), `IncidentOut`, `AuditEventOut`, `EvidenceItemOut`.
5. **Endpoints** (`incidents/router.py`): `POST /incidents` (201), `GET /incidents` (filter by state, paginated), `GET /incidents/{id}`, `GET /incidents/{id}/events`, `GET /incidents/{id}/evidence`. Register in `main.py`.
6. **Persisting evidence:** `save_evidence_bundle(db, bundle: EvidenceBundle)` in the repository (used from Sync 2 onward).
7. **Migration:** `task db:revision NAME=incidents`, review the autogenerated file, `task db:migrate`.
8. **Tests** (`tests/incidents/`): create/read; list filter; every legal transition; every illegal transition → 409; guards; audit row per transition; no update/delete path on audit (assert repository API).
9. README: endpoints and how to try them in `/docs`.

Edge cases: concurrent transitions on one incident → lock the row (`with_for_update`) inside `transition()`; unknown `case_id` → 422 (validated against the manifest file when present).
